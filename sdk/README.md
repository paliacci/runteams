# RunTeams SDK 开发

当前员工与流水线的程序源码、构建和本机工作页面统一使用 MCP Apps：

- 工程 `runteams.creator-project/2`、依赖锁 `runteams.dependencies/2`、发布 `runteams.release/2`。
- 完整员工来源 `/3`；扩展与技能修订 `/v3`，员工发布 `/v4`，工作单 `/3`。
- 检查、导入和构建只验证实际完整源码与固定依赖；不运行作者程序。
- 桌面与浏览器共用一份员工页面、受限 SDK 和原 MCP 进程，权限与原请求回执不变。
- 自测和预览须明确允许执行当前作者源码。未知结果保留原键，只核对原回执，不自动重放。

[本机开发命令](../runteams_creator_dev/MCP_AUTHORING.md)包含检查、构建、自测、预览、打包、
导入与新建工程。[UI Kit](../runteams_creator_dev/UIKIT.md)说明共用主题和组件。
平台工具使用 `runteams_core/devtools/prepare_creator_builder.py` 和 `runteams_core/devtools/export_creator_devkit.py` 导出当前格式；
旧 Wasm 构建器、helper 打包、旧试运行和缺省 legacy profile 已移除，不提供转换或回退入口。

`sdk/ui` 是共用组件与样式源；`sdk/mcp-host` 绑定官方 MCP/MCP Apps 库及受控进程宿主。
原 `sdk/view` 与通用调用帧保留现行上下文和授权合同，不赋予作者平台私有控制地址、凭据或业务权限。
可复用资产、账号与支付仍由云端负责；员工工作、文件和对话仍保存在对应设备作用域。

流水线重构进度见 [实施清单](../design/PIPELINE_REFACTOR_PLAN.md)。当前 SDK 源码可声明并校验、
构建同工程员工组成的流水线，复用原岗位流转字段；构建不会派发工作。
本机工作接口已接通草稿的跨岗执行、接收、退回、人工决定与回执恢复，沿原员工能力、配置及授权运行；
暂停、应用更新、启动的本机控制接口已接通；更新统一冻结各岗位的员工版本与配置，
一次性应用到未完成工作，运行期间继续使用已应用版本，保存草稿不自动切换。
岗位通过仅在流水线工作内开放的 `runteams_pipeline_work` 提交符合原技能声明的结果；
宿主复用既有连线和参数生产者／可见范围决定流转，不将对话结束当成工作验收。
下游读取正式汇报的已提交版本引用；阶段返工留在同一项工作，原员工独立入口保持。
流水线自己的业务工具与工作台使用同一 SDK：可选 `programs` 附件包含完整程序、UI 资源及锁定依赖。
工作台入口、菜单、抽屉与展开复用员工现有界面。发布固定整套程序和所有员工版本，租用只取得签名资产，
不复制工作资料或安装独立员工。取得新版不切换运行；暂停并确认停止后整批应用，再启动，失败保持原版和暂停。
同版本暂停／启动可恢复已授权程序和已打开页面；新版本不继承程序启用授权，未知调用沿原回执，不自动重放。
这些能力已完成源码与隔离签名／真实数据库／本机程序验证；云端候选未部署，也未重分发 SDK 或更新安装包。
R12-07 已完成同一工程的源码与隔离联合验收，包含实际工作台和原会话代理；不能把工程夹具写成新一轮自主业务成果。
默认构建和桌面使用同一种员工对话运行包；正式发布构建显式采用发布合同。
流水线源码约束见 [当前工程说明](../contracts/creator-system/mcp-v1/AUTHORING.md#流水线源码与构建)。
