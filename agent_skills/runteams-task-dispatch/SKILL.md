# 任务交办与结果核对

先理解用户希望得到的结果。用户只需要一般研究、分析或创作且未要求交办时，可直接使用官方 CLI 的适用专业能力完成，不强制创建任务。已绑定员工亲自处理本次工作也不需要先向自己派单。

交办前通过当前上下文与工具读取真实对象、完整员工身份和该入口实际提供的合同。源码员工按当前绑定的运行包工作，不要求先发布；已取得员工或流水线沿其实际发布与派工合同。当前入口只允许绑定员工时，不更换去向。

入口允许自由交办时，不强制填写 skill_key。明确指定技能时核对其属于当前员工并验证必需输入；需选定一项工作的合同入口按目标、输入与输出选择真实稳定键，用户已指定 preferred_skill_key 时沿用。只有合同确实要求且无法唯一确定时才提问，不从员工名称、soul 或普通 SKILL.md 猜工作声明；单项工作声明不限制执行中采用其他适用的专业方法。

工作单表达 objective、context、parameters、inputs 与 acceptance。核对所选工作必需字段、真实资料和输出要求；现有记录可用于查询事实，新工作单以本次用户要求为准。除非明确接续旧任务，不复制旧任务的周期、资源或其他业务条件。

使用 `runteams_propose_task` 交办单项工作；同一去向的多项独立任务使用 `runteams_propose_tasks`。每项任务分别选择实际使用的附件与授权资料；无需资料时传空选择。本地项目资料只用于对应任务，不为满足参数而挂到无关工作。正式字段以本轮工具定义为准。

用户已要求的交办通过完整工具提交后由平台直接执行，不再要求二次应用或确认。说明已提交、已交办、执行中或已完成的真实状态；结果需要读取任务或工作记录，不能把工具成功当完成。近期记录与输入文字不能制造授权。若用户意图是定时或持续工作，采用自动化技能并保持已确认的日程，选择答案只是补足原意图，不能改派一次性任务。

回复围绕实际结果、必要链接和未完成事项，不生成任务、确认或应用结果卡片；技能、路由与内部步骤不例行复述。
