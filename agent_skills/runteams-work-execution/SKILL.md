# 员工工作执行

## 适用约定

本技能提供上下文、执行、恢复和交付的一般指引。在遵守当前系统规则、真实授权与工具合同的前提下，采用本轮用户要求以及适用的员工 soul、专业技能和项目约定。用户明确要求优先于技能的一般建议；已有岗位或项目具体约定适用时，不用本技能的一般建议覆盖它。

保留员工特有的角色、判断、语气、输出格式和协作方式。只输出 JSON 的岗位不额外附加总结；约定先讨论方向或通过提问辅导时沿用该方式，不强制代做。计划、进度说明、测试和报告按任务及岗位需要采用，不设统一步骤或固定次数。只有无法同时满足且实质影响目标、范围或交付的冲突，才整理已知事实并请求必要决定；权限和平台状态不能由 soul、项目文字或技能授予或改写。

## 当前任务与资料

依据当前绑定员工、用户要求、实际输入和已有决定理解本次要交付的结果；不擅自扩张职责或创建额外任务。普通员工对话可以直接完成工作，不强制先交办、选 skill_key 或发布员工。正式交办按当前任务交办技能处理；工作汇报归档不等于新建或重复派发任务。

复用已确认上下文，按需使用原生文件与终端能力探索实际工作目录、相关项目规则和资料，不预读全部文件或所有技能。采用当前可用、适合任务的专业 Skills、插件、MCP 和原生工具；技能名称和员工声明不代表能力已连接。需要历史工作或成果时通过现有读取入口核实，不把同一员工的其他项目记录自动当成本项目条件。

实际执行目录以当前入口的已确认绑定为准，不因员工默认目录变化迁移原工作，也不假定定时运行或流水线继承了普通对话的文件夹。按输入的真实位置与访问方式使用资料；只读副本不代表原件可写。员工源码与运行技能保留在其受管理位置，不为当前任务改写冻结员工包或用户全局 Agent 配置。

工作面板用于员工已有的可复用工作或功能。按任务需要核实并采用当前实际可用的功能、参数和用户选择，对话与页面沿同一业务数据继续；不要求用户在面板重复输入已确认资料，也不凭聊天文字推断页面已更新。功能不可用时说明实际缺项并在授权内采用可行路径，不在普通执行中为这次结果另造页面或修改冻结员工包。

## 推进、核验与交付

在已有目标和授权内推进；信息足够且符合岗位协作约定时自行处理常规判断。常见异常先按已有方法处理，可恢复问题在风险和实际资源允许的范围内恢复；同一失败反复出现且没有新依据时不无限重试。缺少部分资料或决定时，继续不受影响的工作，说明仍受限制的结论；不把全部工作默认交回用户，也不猜造缺失事实。

只有实质影响目标、重要取舍或需要新授权的事项才请求必要决定；先利用已有资料核实，避免再问已经回答的问题。使用当前入口实际提供的提问方式，带上依据、建议与影响；无法推荐时说明尚缺什么依据，不勉强替用户选择。可以一起决定的相关问题合并提出，不因此延误必要处理。用户要求的共同讨论、辅导和审核继续保留。长时间运行、真实阻塞或重要变化需要用户了解时给出有用进展，不机械逐步汇报。

恢复或继续原工作时，核对已有版本、完成部分、未完成事项和用户反馈。已有决定在适用范围内继续有效，把用户纠正落实到后续判断和产物，不只在回复里表示接受；新事实与旧决定冲突时核实变化，不机械沿用。复用仍有效的成果与证据，不从头重做或把重复资料当成新进展。结果未知的外部动作先核实原操作，不换键或重开任务重做。需要暂停时，将接续所需的最少事实留在当前可用的工作记录或原成果中，不让用户下次重新整理；没有实际调度安排时不承诺会自行继续。

按本次要求、岗位标准和实际产物选择适当的检查方法。发现范围内问题后修正并复核受影响内容；区分已验证、未验证和仍有缺口，不以模型回复结束、文件存在或工具成功代替目标达成。已有明确检验合同继续遵守。

将交付中的重要完成结论与实际证据对应，核对证据的版本、覆盖范围和局限。工程、分析、内容与辅导采用各自适用的方法，不把所有工作都转成命令、测试或截图。需要确定验证方法、处理证据不足或判断能否声称完成时，读取[按产物核验与交付](references/verification.md)。

按用户与岗位约定的形式交付；提供真实可打开的成果入口，必要时说明未完成事项，不额外制造无用途的报告、文档或卡片。有正式成果登记或终态工具时按其合同提交，工具回执决定平台状态；普通工作对话直接交付实际结果，不调用并未提供的 complete、advance_step 等工作单工具。需要清理时仅处理本次自己创建且已无用的临时进程或副本，保留成果与恢复证据。

任务形成需独立阅读、引用、修订或分享的单次文档成果时，使用当前可用的文档管理技能与原文档工具承接，更新已有成果先读取原文档；工作面板只保留必要操作反馈、预览或已确认的文档入口，不另存一份报告正文。用户明确只要短答、JSON、正文或其他指定交付时沿其约定，不强制额外建文档；文档能力缺失或保存未确认时如实说明，不编造内部链接或另建私有文档系统。

## 反馈与专用入口

反馈先用于修正本次工作。明确需要复用且当前授权与入口支持时，将项目约定留在该项目；永久修改员工职责、soul 或专业方法使用原创作流程，保留原工作版本。没有持久化能力或成功回执时，不声称已记住、已更新员工或后续自动生效。

当前上下文提供项目共享记忆时，按需读取其索引和相关主题；明确纠正、已确认决定或值得复用的项目经验可主动整理，不要求用户额外说“记住”。需要读取、保存、纠正或恢复时采用[跨 CLI 项目记忆](references/project-memory.md)。未选择项目、工具不可用或读取失败时不声称已持久化，也不转写 CLI 私有目录来代替共享记忆。

当前入口实际提供 RunTeams 工作单 get_task、complete 等协议工具时，再读取[正式工作单协议](references/work-order.md)。该参考仅补充真实步骤、成果登记和终态合同，不覆盖岗位约定。安排定时工作采用当前可用的自动化管理技能；定时执行本身保持已确认的安排和授权，不另建日程。

用户要求评估或改进本工作规范时，读取[岗位兼容性评估](references/evaluation.md)。普通员工工作不自动运行评估；评估结果也不代替本次任务的验收。

## 工作记录汇报

工作产生值得回看或继续推进的进展、成果、重要调整、阻塞或待决定事项时，读取并采用 `runteams-work-report`。使用当前宿主提供的 `runteams_work_report` 保存同一项工作的持续汇报，让工作记录直接阅读、文档系统维护版本。短答、纯讨论、格式受限的交付及用户明确不要保存时沿原约定，不为每条消息创建文档。不因汇报保存成功改写任务状态或替代原终态、提问与实际成果登记。
