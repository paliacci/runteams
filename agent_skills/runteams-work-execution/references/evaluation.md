# 岗位兼容性评估

仅用于有明确要求的工作规范评估，不在日常工作中自动增加评估轮次或模型调用。

随包 `evals/evals.json` 提供 JSON 审计、提问式辅导和项目内容编辑用例；`files` 相对本技能目录。评估时在各自独立的临时项目目录准备同一组文件，把 `soul.md` 作为该测试员工的岗位约定，当前 Skill 作为通用工作指引。用相同任务、模型、运行参数和工具条件比较修改前后的完整 Skill 目录，分别开启新会话，不把评分标准或另一版本的输出放入任务上下文。

每例只将所列夹具复制到项目目录；被评估版本提供 Skill 正文与相关参考，`evals` 目录、expected_output 和评分文件留在评价侧，不复制进该工作区，避免答案泄漏。

只提供夹具所需的工具；普通工作对话用例不提供 get_task、complete 等正式协议工具。使用隔离副本，输出保存在测试目录，不能读取真实客户资料或写入正式员工、项目、日程和外部业务。采用实际可用的原生 Agent 入口；没有授权或可用模型时，只验证夹具和记录待评估项，不填造成绩。

按用例核对实际结果：JSON 岗位检查能否解析、字段与计算是否正确、是否夹带额外说明；老师检查是否保持有效的引导提问，是否过早给出答案；编辑检查是否使用项目材料、数字与引用是否准确、是否保留语气和交付形式。客观部分用程序校验，教学质量、文字质量与不必要流程由人工评阅，不能只凭关键词判定通过。

面板与文档用例需另提供隔离的能力与文档回执，检查是否复用已有功能和用户参数、沿原文档身份修订、保留未知保存状态，以及没有在执行中重写员工页面或创建第二份成果。只有静态材料而无可调用工具时，仅评价处理方案，不能算作已完成真实 UI 操作或文档写入。

保留每次实际提示、输入、输出、运行成功／失败／未执行状态、模型、耗时和可取得的 Token 信息。报告逐例的新旧差异、证据与退化；少量单次用例只支持该范围内的判断，不宣称普遍提升。需要判断稳定性时增加独立重复运行和不同任务。

## 连续委托与汇报负担

[连续委托场景](../evals/continuous-delegation.json)由评价者逐轮投放，不是普通单轮用例。它同时检查执行与汇报内容；采用待测执行 Skill 及其当前可用的汇报 Skill，保留两者版本。首次及恢复会话提供 setup_message，每轮只投放对应 message 与 inputs，不把后续输入、assertions 或整个场景文件交给被测 Agent。恢复轮使用同一对照分支自己的真实产物；缺失产物应记录为恢复失败，不能由评价者补写标准答案。

先比较新旧完整技能组合，再用同模型、相当工具、同等历史与文件保存条件下的通用 Agent 加合适专业 Skill 作为价值基线；基线可以自行维护上下文，不人为移除其能力。专业方法在各分支一致，具体资产和版本记录在评估结果。连续各轮沿各自分支接续，独立重复实验才重置，不能每轮都从零开始。

检查实际产物是否复用有效事实、去重、落实纠正、推进不受阻部分、保留限制，以及汇报能否让用户迅速判断变化和必要决定。记录初次设置、解释、阅读审核、纠错、催促和恢复的用户时间；模型运行时间不能代替用户时间。没有真实计时则报告重复提问、被纠正后复发、误报、遗漏、恢复是否成功等可观察事实，不生成省时百分比或任意综合分。成果质量下降、隐瞒问题或省略必要审核不能算减负。

随包场景只授权隔离文件操作，验证连续工作与汇报内容，不验证平台文档保存、自动触发、真实业务效果或跨设备恢复。平台能力另用实际可调用入口验证；静态工具回执和模型自述不能替代执行证据。正常员工工作不自动运行这组评估或生成管理负担报表。

根据真实产物和执行记录调整规范，避免把某个用例的答案或格式变成所有岗位的通用要求。确认新增规则改善了目标行为，再复核是否破坏其他岗位。方法借鉴 [Anthropic skill-creator](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md) 的版本对照和人工／客观评估分工。
