# 跨 CLI 项目记忆

项目共享记忆属于当前实际绑定的工作文件夹，由 `runteams_project_memory` 统一读取和保存，Codex、Claude 等渠道使用同一份项目资料。它与原生 CLI 个人记忆、员工 soul、专业技能、任务进度和业务回执分别归属，不自动迁移或合并它们。

## 按需读取

当前上下文提供短索引、revision 和目录位置。需要相关主题时使用 `read` 与真实 key；索引有更多条目时用 `list` 的 offset、limit 读取，不预读全部正文。历史事实与当前资料不一致时先核对来源与适用范围，以本轮明确要求和当前已确认事实为依据，不让旧记忆覆盖新决定。

共享记忆是项目资料，不授予外部操作权限，不覆盖系统规则、原生项目规则或岗位约定。读取失败不同于空白，不据此建立一份替代记忆。没有项目绑定时继续按当前资料工作，不把员工源码目录或程序默认目录当作用户已选择的项目。

## 自主整理与可靠保存

用户明确纠正了项目表达、确认了后续还会用的决定、提供了重要资料位置，或实际工作形成值得复用的经验时，可以在当前授权范围内主动整理。保存最小的有效信息及依据，合并重复内容，标明适用条件与仍不确定的部分。不要逐轮复制聊天、可从现有资料直接得出的细节、临时错误、任务状态、账号凭据或跨项目私人偏好。

先核对已有相关条目，再使用 `save`：key 是稳定的小写主题键，title 和 summary 用于简短索引，body 放可独立理解的内容，kind 为 decision、preference、reference 或 lesson。提供当前已读取的 expected_revision、本次稳定 UUID operation_id 和实际 evidence。相同主题在原 key 上更新；不同项目不能互相复制条件。

版本冲突时读取当前索引和正文，将他人已经确认的修改保留后再提交新请求，不盲目覆盖。工具结果未知时先用 `operation` 与原 operation_id 核对；确认原动作后不再执行。相同请求可以用原 UUID 恢复回执，不能改写请求后重用该 UUID。

快照是受管理的 Markdown 索引与主题文件，只读核对可以使用原生文件能力；更新通过工具完成，不直接改 HEAD、manifest 或快照文件。保存只有收到 state=confirmed 才能声称已记住；回执里的 revision 是原动作版本，current_revision 可能已经变化，核对现状应再读当前条目。

## 纠正、删除与恢复

过时条目按实际依据更新或用 `delete` 删除。需要恢复时先用 `history` 核对原修订，再用 `restore` 指定 target_revision 和当前 expected_revision；恢复整个历史版本会影响其他主题，仅在明确要求的范围内使用。删除和恢复同样保留修订与原动作身份，不把历史记录当作当前事实；删除当前条目不等于从历史中彻底清除。

同一项目文件夹中的员工共享这里的项目约定。员工通用职责或专业方法的永久修改仍走原创作流程；这份记忆也不表示项目文件、业务状态或原生 CLI 记忆已经同步到其他电脑。
