# RunTeams 手机端 · 产品经理重构规格（设计完工标准）

> 由「借流水线 03 产品经理」思路产出，但适配为**存量 app 的产品批判 + IA 重构**：
> 以真机扫描（`design/scan/app/*.png`）为 ground truth，不凭空写 PRD。
> 产品边界已由 `ios/README.md` 定死，PM 只动屏级 IA，不动定位。

## 0. 产品边界（不改，来自 README）
- 手机 = 桌面的**远程伴侣**。三件事：① 远程查看进展 ② 人工介入（流水线自己走不下去时）③ 紧急控制（暂停/恢复/取消）。
- **不**在手机跑 Agent；**无**任何购买/升级/支付入口；看板/卡片/工作记录严格**只读**。
- 情绪内核：AI 团队在你电脑上 24h 跑，**只在需要人时才打扰你**。→ **健康 = 安静**。
- 强 E2E 加密、设备签名、防重放；这是信任资产，设计要让用户**感到安全**。

## 1. 核心洞察
手机上用户只有两种时刻：**① 瞟一眼"团队还好吗"（ambient）② 有事找我，做决定（act）**。
IA 按这两种时刻建，其余（看板/日志/历史）是二级参考。

## 2. IA：5 tab → 3 tab + 提脊的人工闸

| 新 | 收纳旧的 | 说明 |
|---|---|---|
| ① 首页 · Pulse（新） | 运行中 + 全局概览 | 落地答"团队还好吗"；有事→人工闸横幅置顶；健康态专门设计 |
| ② 活动流（合并） | 待你处理 + 运行中 + 最近完成 | 一条时间线三状态，筛选：待办/进行中/已完成；待办项优先置顶 |
| ③ 看板（重想） | 流水线 | 竖向阶段列表，非横向桌面移植 |
| 设置 | 设置 | 降为首页右上角头像入口，底部留 3 tab |
| 人工闸决策（hero 流） | 待你处理详情 | 提为核心流，贯穿首页/活动流 |

旧屏映射（无一丢失）：
- 登录 → 保留精修
- 待你处理 → 人工闸流 + 活动流"待办"筛选
- 流水线 → 看板（竖向重想）
- 运行中 → 首页 Pulse + 活动流"进行中"
- 最近完成 → 活动流"已完成"
- 设置 → 首页右上角头像
- Live Activity（锁屏）→ "出 app 的瞟一眼"，设计保持同一语言

## 3. 目标屏清单（= 设计完工标准，逐屏出稿）
1. **登录** —— 邮箱 OTP + E2E 说明，精修
2. **首页 Pulse · 健康态** —— 团队在干活、无需你，安静但不空洞（hero，定气质）
3. **首页 Pulse · 有事态** —— 顶部人工闸横幅 + 正在工作行（hero）
4. **人工闸 · 决策详情** —— 为什么停 / 继续会怎样 / 已试N·交付M·等待 / 立即重试·终止（hero，最高火力）
5. **活动流** —— 时间线 + 状态筛选（待办/进行中/已完成）
6. **看板 · 竖向阶段列表** —— "团队现在在哪一步"（借 Vibe Kanban「列=员工」北极星，手机竖向）
7. **看板 · 阶段→卡片 / 卡片详情** —— 只读逐层下钻
8. **设置** —— 账号 / 桌面配对（等待电脑上线）/ 通知
9. **Live Activity 锁屏聚合**（可选，保持语言一致）

## 4. 设计发力优先级
hero 3 屏先做、定 design system：**#2/#3 首页两态 → #4 人工闸决策 → #6 竖向看板**。
锁定语言后铺 #1/#5/#7/#8，再延展 desktop/web。

## 5. 扫描暴露、设计必须解决的 4 个原型病
1. 过度按状态拆 tab（3 个常空）→ 合并为活动流。
2. 灵魂功能（人工闸）被埋成平级 tab → 提为主脊。
3. 横向看板搬桌面 → 手机竖向重想。
4. 空状态纯文字 → "安静=健康"当状态设计，不留白。
