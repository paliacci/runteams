# RunTeams 产品文案

## 产品理念

RunTeams 把复杂的 AI 编排藏在清楚、可控的工作界面之后。用户不需要学习代理框架；他只需要组建团队、交代任务、查看进展，并在真正需要判断时介入。

我们的老师是 Apple 的克制与乔布斯的取舍：先呈现结果，再解释机制；一个界面只强调一个下一步；能删掉的概念，不换一个术语继续解释。

## 语气

- 清楚：使用日常动词，先说发生了什么。
- 简洁：一句只表达一件事，不重复标题。
- 冷静：不夸大、不卖弄 AI，也不把正常等待写成故障。
- 可行动：错误、空状态和确认框都给出明确下一步。
- 尊重：不责怪用户，不用“错误操作”“你没有”等表达。

## 术语

| 使用 | 避免 | 说明 |
| --- | --- | --- |
| 任务 | 卡片 | “卡片”只用于开发和布局语境。 |
| 岗位 | 节点、环节 | 表示流水线中的工作位置。 |
| 员工 | 成员、Worker、Agent | 表示承担岗位工作的 AI 员工。界面不强调技术实现。 |
| 模型渠道 | Agent Channel、供应商 | 表示 Codex、Claude Code 等运行渠道。 |
| 团队规范 | Skill（用于横向规则时） | 多个岗位共同遵循的规则。 |
| 工具连接 | MCP Server | 面向用户说明外部工具或数据连接。 |
| 交付文件 | 产物、Artifact | 任务运行生成的文件。 |
| 人工确认 | Gate、人工决策点 | 需要用户决定下一步的岗位。 |

## 组件规则

- 页面标题：名词或用户目标，例如“模型渠道”“创建流水线”。
- 按钮：动词开头并说明结果，例如“创建任务”“保存更改”“继续运行”。
- 状态：描述当前事实，例如“运行中”“等待回复”，不用按钮式措辞。
- 状态控件：常驻文案显示当前状态；点击后的动作放在悬停提示、菜单或无障碍标签中。
- 空状态：第一句说明现状，第二句给出下一步。
- 错误：说明失败对象和恢复方式；保留技术细节给日志。
- 技术信息：默认界面使用产品语言；命令、协议和数据格式只在用户主动打开的高级视图中展示。
- 确认框：标题说清动作，正文说明影响，危险按钮重复具体动作，不使用泛化的“确定”。
- 成功提示：说清已经完成的结果，不使用“操作成功”。

## 标点与格式

- 中文界面使用全角中文标点。
- 按钮和短状态不加句号；说明性完整句使用句号。
- 数字与中文量词之间不留空格；英文产品名、版本号和中文之间保留一个空格。
- 同一对象在同一页面只使用一个名称。
