# RunTeams 桌面端 · 产品重构 + 视觉种子（设计完工标准）

> 同 app 流程：先扫真实产品（跑 `app.py` + `web/index.html`）→ PM 重构 IA → 视觉种子 → hero 锁语言 → 铺全套。

## 0. 扫描结论（真实产品，非假设）
桌面端 = **自包含 macOS app（Chrome app 模式壳）加载 `web/index.html`**。本质是一个
**对话驱动的 AI 团队编排台**，不是普通的任务看板。两个核心视图：
1. **对话主页**：「我们想要做些什么？」+ 四张动作卡（搭建流水线/启动工作/调整流程/创建成员）+ 底部聊天输入框（带模型选择 Opus/思考档）。= 编排入口，chat-first。
2. **流水线看板**：流水线唯一操作界面，横向列=岗位或状态，卡片带运行状态；岗位、处理结果和去向都在看板内配置。
其余：对话线程（创建员工…）、待你处理(人工闸)、团队成员、扩展、新建流水线、账号、卡片详情。

> 主轴是对话编排，看板负责日常运行与结构配置，不再维护一套独立画布。

## 1. 视觉种子（关键决定）
- **warm-dark**：用 rt.css 的**深色变体**（`--bg:#171513` 暖墨底 / `--panel:#211f1d` / `--ink:#ece9e3` off-white / 琥珀 `#d9a04a`·绿 `#4bc383`·红 `#ec7a70`）。
- 理由：pro 编排台长时段使用→暗色；现产品即深色；仍是**同一套 tokens**，与 app(亮)/web(亮) 同系统、按场景切默认主题。
- 字体沿用 Hanken Grotesk + IBM Plex Mono（mono 承载 Token 数/时间/模型名/版本号）。
- 状态色只承载语义；推进、打回、放弃等处理结果复用状态色族。
- 签名：等宽数字、"列=员工"、暖墨暗底 + 极克制的描边、聊天气泡低调。

## 2. IA（桌面三区骨架）
- **左栏（常驻导航）**：品牌 + 新对话 + 新流水线 + 扩展 · 对话历史 · 流水线列表 · 待你处理 · 最近动作 · 账号。
- **主区（随选择切换）**：对话主页 / 对话线程 / 流水线看板 / 团队 / 扩展 / 设置。
- **流水线内顶栏**：居中名称 + Token + 团队 + 运行状态(已就绪/暂停)，不放视图切换。
- 人工闸：在左栏「待你处理」+ 主区决策面板（复用 app 人工闸三态逻辑，桌面横向布局）。

## 3. 目标屏清单（= 设计完工标准，hero 先做前 2）
1. **对话主页**（hero）：四动作卡 + 聊天输入 + 左栏
2. **看板**（hero）：横向列 + 卡片 + 居中标题与运行控制
3. 对话线程（编排对话：用户说需求→助手拆成流水线/建员工，带工具调用块）
4. 卡片详情抽屉（右侧滑出：状态/产物/工作记录）
5. 人工闸决策面板（桌面横向：为什么停/交付/三态动作）
6. 新建流水线（对话式或表单）
7. 团队成员（员工卡列表：角色/模型/工具白名单/max_iter）
8. 扩展（连接器/MCP）
9. 账号 / 设置
10. 登录

## 4. 发力顺序
warm-dark 设计系统 tokens（rt-desktop.css）→ hero 2 屏锁语言 → 铺其余 → 与 app/web 同源校验。
