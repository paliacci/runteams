# 开发指南

使用 Python 3.12。前端／SDK 检查使用 Node 24.22.1，依赖按各工程的 npm 锁安装。

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/python -m pip install -r requirements/build.txt
npm ci --prefix tooling/js --ignore-scripts --no-audit --no-fund
```

## 日常检查

在仓库根目录执行源码和仓库检查：

```sh
.venv/bin/python -B -m runteams_core.devtools.check_source
.venv/bin/python -B -m runteams_core.devtools.check_ui_boundary
.venv/bin/python -B -m runteams_core.devtools.check_repository --root . --namespace runteams_core
```

核心业务目录见[模块索引](core-domains.md)，新目录须在 `tooling/core-domains.json` 登记。

仓库检查读取 Git 跟踪文件；新增、移动或删除源码后，先暂存拟提交文件。它检查生成物／私密文件、个人机器路径、目录大小写冲突、文档导航与工具清单。

修改工具后重新生成清单：

```sh
.venv/bin/python -B -m runteams_core.devtools.command_inventory --root . --namespace runteams_core
```

提交源码后运行统一 CI，输出目录使用仓库外的新目录：

```sh
.venv/bin/python -B -m runteams_core.devtools.ci \
  --output /absolute/path/to/new-ci-output \
  --sdk-tsc "$PWD/tooling/js/node_modules/typescript/lib/tsc.js"
```

统一入口覆盖源码边界、仓库卫生、可复现 wheel、独立安装主流程、PDF 附件及 SDK 消费者检查。GitHub 工作流运行相同入口。针对业务变更补充对应的定向测试；一次 CI 通过不表示所有平台、真实模型或长期运行均已验收。

共享界面修改还会运行宿主接口测试与 wheel 内的 UI 边界检查。新增页面应按[宿主边界](ui-host-boundary.md)决定归属，不能把发行版分支或商业实现放在公共 UI 中再隐藏。

同源实体跨面板展示时必须复用同一个组件及数据适配器。员工模块的独立任务与流水线任务共用任务详情标题、元信息、章节、滚动恢复和交付物呈现；任务类型只提供适用的操作与内容，不再维护独立员工任务的第二套详情页面。有任务归属的工作记录（包括已完成任务）统一进入任务详情，交付文档从交付物打开；没有任务归属的历史汇报与执行下钻继续保持只读。任务、岗位执行和汇报分别标明范围与统计单位；任务内入口只展示当前任务。工作记录列表项、执行列表与执行详情由 `web/ui/work-records.js` 统一维护，流水线面板只负责上下文与业务操作，禁止另外拼接一套执行摘要、状态、时间或详情。调整时同时验证数据归属、重试保留、跨入口一致及返回后的草稿和阅读位置。 同源记录行的 hover 与键盘焦点范围都应铺满抽屉正文宽度，文字保持正文内边距；由共享列表样式统一处理，不能在嵌入任务详情后缩成局部色块。

## SDK 开发包

SDK 源码直接在本仓库维护。独立开发包由同源导出器生成，无需第三个仓库：

```sh
.venv/bin/python -B -m runteams_core.devtools.export_creator_devkit \
  --output /absolute/path/to/new-devkit \
  --runtime-root /absolute/path/to/verified-mcp-runtime \
  --libraries /absolute/path/to/verified-author-libraries \
  --esbuild /absolute/path/to/verified-esbuild
```

包内 `runteams.py` 可检查、构建、打包和新建工程；开发机仍需 Python 及声明的依赖。Node 和编译器随开发包提供。macOS ARM64 的 `devkit.yml` 手动工作流从固定锁准备运行资源，再核对原开发主流程。

不要把模型密钥、真实工作资料、浏览器缓存或验收截图提交到仓库。模型调用和对外部署与本机检查分别执行。

SDK 工作台页头遵循公共抽屉规范：顶部 8px、水平 20px；标题 22px/32px、字重 600；描述 12px/18px、字重 400，距标题 8px。公共实现位于 `web/ui/kit/components/styles.css`，用 `python3 sdk/ui/build.py` 生成 SDK 分发，`--check` 校验同源，禁止在示例里另加覆盖。SDK 资源与文件预览不额外添加 section 标题的例外保留。

流水线新建任务在起始岗位列内出现普通的纯标题卡片，不使用右侧抽屉，也不另设计编辑卡片。外框和标题直接复用 `.card.title-only`、`.card-head`、`.tt`；标题字重、字号、行高和边距由普通卡片的公共规则决定。默认只有任务名称，无图标、附件按钮、参数区和创建按钮。非空标题结束编辑即自动提交：失焦或 Enter 后保留 5 秒缓冲，期间重新聚焦标题取消本轮计时，修改后失焦重新计时；Esc 取消，空标题不提交。输入法组词不提交。排队期间复用普通卡片的中性状态点，不增加表单或额外确认按钮。离开看板仍沿原流水线提交，切换账户或设备归属取消未发送的排队操作。岗位参数使用现有默认值，仅在提交时缺少必填项才显示对应输入，不能绕过合同校验。复用当前受理及回执核对流程；切换岗位保留草稿，Esc 取消当前草稿。受理结果未确认时必须沿用同一个操作，不能另建任务。后台刷新不能清空草稿或打断输入焦点。历史记录中已找回的带资料按钮和参数区版本，不等于用户描述的纯标题版本，不应再次标为该版本的原样恢复。

流水线卡片右上角只保留单个悬浮更多按钮，白底、细边框和轻阴影；编辑操作收进更多菜单。正式任务固定显示查看详情、编辑任务、开始任务、停止任务、移到垃圾箱五项，顺序不变；状态只决定可用性，不可用项置灰并说明原因，鼠标和键盘均不能执行。悬停、键盘聚焦及菜单打开时显示，不占用标题宽度。右键和 Shift+F10 复用 `cardContext` 菜单，滚动或 Esc 关闭并保留键盘返回路径。新建任务缓冲期打开菜单暂停计时，关闭后重新留出完整 5 秒；编辑已排队任务先原子暂停，保存后保留 5 秒缓冲，手动暂停的任务编辑后继续保持暂停。单任务只提供开始和停止，不再暴露暂停开始与继续工作。新任务仍在 5 秒缓冲后自动开始；暂存或恢复的任务点开始任务后进入原受理或结果核对流程，不能绕过缓冲或重复发送。暂存任务不能被整条流水线启动或更新自动开工。工作中与结束态不可编辑；停止后等待原执行收尾才能移入垃圾箱。任务与记录保留，恢复后未完成任务保持暂停，已完成任务保持完成；发送过的工作恢复后先进入原结果核对流程，不自动重复执行。所有任务操作通过原账本和同一操作编号核对回执。

任务卡片的停止任务与移到垃圾箱点击后直接执行，不再弹二次确认。复用原操作编号、处理中禁用及失败恢复；移入后仍可在垃圾箱恢复，保留任务、记录和交付物。

### 流水线任务卡片：右键入口与停止后开始（2026-11-10）

任务卡片不显示悬浮更多按钮，正式任务和新建任务缓冲卡片通过右键打开原共用菜单；键盘聚焦后仍支持菜单键和 Shift+F10。正式菜单固定五项，继续复用公共菜单样式、禁用原因和操作回执核对。`cardFeedback` 只负责失败与待核对提示，不注入工具条。

已停止（canceled）的任务在原执行收尾后允许开始，沿用原任务编号、岗位访问及工作记录。停止前保存原状态和排队时间；开始时，已确认的人工决定恢复原等待状态，尚未发送的任务回到原排队或阻塞状态；已发送但未确认结果的任务进入原结果核对，不能直接重复执行。旧版停止记录可从已确认的 `pipeline_waiting` 恢复，截图中已存在的待人工决定无需迁移。执行仍活跃或收尾未确认时不可开始，并显示收尾原因。整条流水线暂停时仍须先启动流水线，已完成任务不可再次开始。

回归覆盖停止后同任务开始与回执重放、旧人工决定保留、发送后停止收尾及结果核对。设计提案与 mock 的 M01–M08 同步移除按钮，M06 区分完成与停止。仅在无正在执行任务时更新本机 8791；界面检查不启动真实模型工作。
