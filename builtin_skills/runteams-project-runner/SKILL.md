# 项目运行与试用

对象是工作单 `assets` 里的授权副本（例如 `.runteams/assets/项目仓库`），或工作区内的项目。
原则：**被测项目的数据和实例独立，原生 Agent 能力保持开放，只清理自己启动的实例并留下证明。**
当前官方 CLI 已启用的 Skills、插件、MCP 与浏览器无需绑定即可使用。本包的准备器和浏览器入口是任务环境与审计方法，不是原生能力的权限门槛。

## 0. 运行前准备是必过阶段

需要运行产品或操作网页时，先读项目运行规则并完成隔离副本、依赖安装、`pip check`、实例启动、
接口就绪探测；需要网页交互时确认实际可用的浏览器，再进入依赖运行环境的检查。原生浏览器已经可用时直接采用，不重复安装。不要在环境未就绪时把部分工作称为完成巡检。
准备失败时先读取 `evidence/runtime-preparation/` 完整日志，解决可恢复原因；仍无法运行则清理并报告阻塞，
明确环境尚未就绪，不推进需要运行环境的步骤。

`get_task.run` 给出当前运行编号和尝试次数；checkpoint 的 operation 结果包含 execution/evaluation。
同一操作的回执确认仍复用 invocation_id；已确认失败后重新安装，或 `.scratch` 已被清理后重建环境，
属于新的准备操作，必须用新的 invocation_id（例如 `prepare-project-run-<run.id>`），不能复用旧失败或已失效的成功回执。
有 in_doubt 的操作先核对实际状态，不自动重放。

## 1. 建立隔离环境

先调用 `run_capability` 执行 `isolated-env`（需要为项目数据目录单独隔离时加 `--var 变量名`，
例如 `--var RUNTEAMS_DATA`）。之后**每一条**项目命令都先加载环境：

```sh
. .scratch/env.sh && <项目命令>
```

这份环境仅供被测项目及其测试子进程使用，不覆盖 Agent CLI 自身的配置、登录或原生技能加载。被测项目的 HOME、临时目录、配置和数据落在 `.scratch/`；包下载文件单独复用应用管理的缓存，不混入用户的全局 Python 或项目环境。
端口使用 `RUNNER_PORT_1`、`RUNNER_PORT_2`，不要自己挑端口。

被测项目是 RunTeams 本身时，加 `--runtime runteams`。它自动隔离主数据库、核心数据、员工工作区和凭据文件，覆盖主实例继承的路径；不能仅设置 `RUNTEAMS_DATA` 后就认定所有数据已隔离。
工具会隔离 RunTeams 的持久化数据目录与凭据文件，不连接正在工作的主实例。
文档使用前端编辑器和普通文件存储，无需准备额外的文档内核。

## 2. 识别并运行项目

- 从 README、AGENTS.md、CONTRIBUTING、`package.json`、`pyproject.toml`、`Makefile` 等处找出测试和启动命令；
  工作单指定了命令时以它为准。
- 所有命令都加超时。失败的测试最多重跑 2 次，区分“不稳定”和“确定失败”。
- 原始授权副本保持只读。需要运行时把源代码复制到 `.scratch/project/`，依赖、生成文件和测试数据也只写入临时目录。
- Python 项目有 `requirements.txt` 时调用 `prepare-runtime project --project .scratch/project`；之后使用返回的 `.scratch/project-venv/bin/python` 运行项目。工具仅在任务内创建 venv 并按项目声明安装，不修改全局 Python。默认寻找 Python 3.10+，可用 `--python` 指定兼容解释器。
- Node 或其他项目按其锁文件/README 使用对应管理器，仅在上述临时副本中安装；不猜包名、不改依赖版本来掩盖测试失败。
- 安装后必须通过依赖一致性检查；使用返回的解释器执行全部项目测试及启动命令，不退回系统 Python 掩盖环境失败。
- 平台提供应用数据目录内的包下载缓存，重复任务复用下载结果；venv、项目数据、配置和浏览器会话仍独立放在 `.scratch`。官方浏览器二进制与 npm 下载也复用受管缓存；产品首次安装固定的已验证版本，后续复用已安装工具，仅核对任务副本版本，浏览器会话/配置/用户数据始终隔离。缓存不代表环境就绪；项目仍按声明安装依赖，浏览器工具复用已安装版本并检查启动与关闭，不借用用户全局安装。
- 因缺少解释器、系统库、网络或安装超时导致失败属于**准备阻塞**，不记为项目缺陷。完整分阶段日志及安装版本清单留在 `evidence/runtime-preparation/`，超时也保留已输出日志。准备工具需要包源网络，项目依赖安装仍限制在 280 秒内；官方浏览器首次下载允许较长准备预算（整次工具最多 900 秒），后续复用受管缓存。准备耗时必须单独记录，未就绪不算已经开始巡检。

## 3. 启动产品实例并实际使用

- 在副本里启动，使用隔离环境的数据目录变量和 `RUNNER_PORT_*`。优先使用当前 Agent CLI 原生的可持续会话与停止能力，按实际工具说明确认启动、读取与停止方法。Codex 提供这些工具时可用 `exec_command` 的 `tty=true` 启动，短等待返回 session_id 后用 `write_stdin` 读取同一会话；停止时向该会话写入 Ctrl-C（\u0003），继续读取直到确认退出。其他渠道以本次原生工具说明为准，不能猜工具名或把会话号当 PID。
- 使用前台会话时，启动命令保持前台，例如 `. .scratch/env.sh && exec <启动命令>`；将会话或后台任务标识、启动命令、工作目录、登记端口和日志证据保存在 `evidence/instance-session.json`。定期检查实例仍在运行，准备与业务步骤分别设有界时间预算。
- 渠道支持受管后台任务时也可使用；保存本任务的会话或任务 ID、PID、日志和端口，核实进程身份后仅停止自己创建的进程及子进程，不按全局进程名批量停止。
- 启动前确认有可靠的停止与清理方法。原生会话暂时不可用时先检查其他原生进程管理方式；仍无法清理才报告准备阻塞。会话丢失或停止失败时保留日志与残留证据并尝试恢复，不能新启实例掩盖旧残留。

- 用 `http-probe` 等待实例就绪，再按用户路径实际使用产品：打开页面、调用接口、提交表单、读取结果。
  路径依据规格文档、README 或工作单里的关键场景，不要随意乱点。
- 每一步都用 `http-probe --out evidence/<步骤>.json` 留下请求与响应证据；需要检查页面时确认页面能加载、
  包含预期内容。
- **绝不**连接用户自己正在运行的实例、真实数据库或外部服务；`http-probe` 只允许本机地址。

### 复用官方浏览器技能

浏览器操作使用微软维护的 [Playwright CLI + Skills](https://github.com/microsoft/playwright-cli)。RunTeams 只准备任务环境和留证约定；点击、输入、截图、快照、网络检查、录制和 trace 直接调用官方命令。

1. 当前官方 CLI 提供可用浏览器时，按原生技能创建独立任务会话并验证打开与关闭。需要本包环境时调用 `prepare-runtime browser`：它首次安装产品指定版本的官方 CLI，之后复用应用管理的已验证安装，并给任务建立 `.scratch/browser-runtime` 独立副本（macOS 优先写时复制），优先使用已安装 Chrome 的全新无头会话；没有 Chrome 时才下载受管 Chromium。真实打开空白浏览器并关闭通过后才视为就绪。首次安装包含官方 `install --skills=agents` 的配套技能，后续随工具副本复用。用户明确要求升级时，在全新准备任务调用 `prepare-runtime browser --upgrade`；验证失败保留既有可用版本，不在当前任务中升级。读取所采用入口的技能与所需官方资料，不套用旧版 JSON 场景或 `browser-scenario`。
2. 采用本包浏览器环境时，通过 `run_capability` 调用 `runteams-project-runner/browser-cli`，arguments 原样使用官方 CLI 参数，例如 `["-s=first", "open"]`、`["-s=first", "goto", "http://127.0.0.1:<登记端口>/"]`。先用 `["--help"]` 确认当次命令。适配器加载任务环境并为 open 注入本任务配置，完整命令与原始结果保存到 `evidence/browser/cli-calls/`。原生浏览器和官方 CLI 命令也可直接使用；按所用入口保存等价的运行版本、截图、操作与清理证据，不要求绕行本包。操作语法、定位与录制以当次官方技能为准，适配器不实现浏览器动作。操作本任务登记的隔离实例，本包配置限定已登记端口，不限制其他原生能力。
3. 从实际页面快照选择目标，通过采用的原生入口或本包入口执行官方点击、输入等操作。不要连接用户浏览器、用户登录资料或其正在运行的实例。界面缺陷必须实际操作界面；接口调用、页面提供的 WebMCP 工具不能替代这一步。
4. 从打开的空白浏览器启动 tracing/recording，再导航到入口。关键步骤截图、快照、console、requests 和复现脚本保存在 `evidence/`；自动生成的文件由配置放入 `evidence/browser`，显式文件名须写 `evidence/...`，不得留在临时依赖目录。
5. 对疑似缺陷关闭本次会话，在全新会话从入口再次执行；分别保存两次结果、预期来源、实际页面及源码版本。按当前官方技能生成可重复执行的 Playwright 脚本或保留完整命令记录。不要把瞬时元素 ref 当成跨会话稳定定位。对空白等精确要求读取实际 DOM 字符串，不能仅靠会规范化空白的文本断言。
6. 操作报错、定位错误、外部请求被阻止、缺少依赖均不直接算产品缺陷；先依据实际页面和日志判断。真实断言失败也需核对规格并独立重复。不能完成界面验证时明确写未覆盖，不能改用旧工具静默宣称完成。
7. 将截图、trace、复现步骤及 `evidence/browser/runtime.json`、`package-lock.json` 打包并 `publish_artifact`；问题通过问题协作保存，结论写入任务结果。只有用户需要独立阅读或分享的产出时才写文档，不为执行过程另建报告或台账。路径只是任务文件位置，注册后才是交付。获取最新版失败属于环境未覆盖；同一任务重复准备沿用已安装版本，不在复现中途升级。

这条路径适用于后台 CLI 网页任务。Codex 桌面版的内置 Browser/Computer Use 不等于 CLI 可用能力；桌面应用任务按当前渠道实际提供的原生工具执行，无需显式挂载。没有相应工具时如实说明未覆盖，不得声称本包提供了整个电脑操作。

## 4. 清理并证明

1. 原生浏览器使用其会话关闭方法并核实退出；本包环境通过 `browser-cli` 调用官方 `["close-all"]` 关闭本任务的会话（HOME 已隔离，不影响其他任务）。关闭失败保留证据并报告清理阻塞，不使用会扫描整台电脑的 `kill-all`。保存最后的会话列表和清理结果。
2. 使用登记的原生会话或后台任务管理能力逐个停止自己启动的实例并核实退出；确认子进程已退出、登记端口与产品另行分配的端口均已释放。不能仅凭发出停止动作就算成功；
3. 确认进程退出后删除 `.scratch/`。若任务副本内含只读目录，仅恢复该隔离目录内副本的删除权限；不得改变授权原件或工作区外权限。退出未确认时不得删目录；
4. 完成全部报告、证据文件、文档与附件登记及步骤推进，准备好完整 `complete` 参数，再调用最终 `cleanup-verify`。它是提交前的必过检查：隔离目录仍在、仍有进程引用它或端口仍被占用时都会失败。
   通过后直接 `complete`，不要再写工作区文件，也不要把最后回执另存文件或重新登记附件；工具回执已有平台持久审计。任何后续工作区修改都会使最终核验失效，必须重新 `cleanup-verify` 后直接提交。可在整理报告前先做一次清理检查并保存证据，但它不能替代内容全部完成后的最终核验。
   清理不掉时调用 `report_blocked` 并列出残留，不得静默结束。

保留下来的只有证据文件（例如 `evidence/`）和本技能 work 声明的交付物。

## 官方网页测试方法整合

开始网页测试时读取 `upstream/webapp-testing/SKILL.md`，按需使用其中的示例和 `scripts/with_server.py`；固定来源与许可证见 `upstream-sources.json`。相对资源路径属于该上游目录，原文和脚本未修改。

采用先观察实际页面、确定选择器、再执行用户路径并保留截图和日志的方法。当前 Runtime 有原生浏览器或已经准备好的官方 Playwright CLI 时继续复用；上游的 Python Playwright 方式是另一种可用方法，不强制重复安装或替换现有浏览器。需要时在本任务环境准备 Python Playwright，不能把“依赖未准备”写成项目缺陷。

等待本次操作所需的真实可见状态或请求完成；持续轮询页面不应因始终无法 networkidle 而卡住验收。`with_server.py` 只能管理本任务创建的隔离测试实例，遵守本包既有端口、数据、会话登记和清理规则。检查发现的问题交给现有缺陷分析/问题记录，不能只凭截图或成功启动判定功能通过。

## 正式工作与代表样例

工作范围和完成标准见 [runteams.json](runteams.json)，代表样例见 [references/work-examples.json](references/work-examples.json)。只把实际执行且读回核对的结果称为工作完成；结构、健康检查和模拟分别记录。

真实运行和清理后，将场景、观察、证据引用、未覆盖范围及清理结果汇总为 `evidence/run-report.json`；内容符合本技能 work.output_schema，不能只登记退出码或文件存在。
